# マニュアルの文章の書き方

deck.json の `title` `steps` `note` `extra` `cards` `rows` と、動画の `say` を書くときに読む。
読み手は「この管理画面を初めて触る、クライアントの担当者」。WordPress の用語は知らない前提で書く。

この決まりは、スキルが出した文章を人が手直しした実例（下の「手直しの実例」）と、日本語推敲スキル japanese-writing-unified（natural-japanese-structure を含む）のうち、マニュアルに当てはまる部分をまとめたもの。

## 1. いちばん大事なこと：入力した内容が「サイトのどこに出るか」を書く

管理画面の欄の名前だけを説明しても、読み手は何が変わるのかわからない。次の3つを必ず入れる。

- **タイトルの下に、その画面で編集できるページを書く**（`where`）
  - 例：「この編集機能があるページ：「新卒採用」「中途採用」」
  - 例：「この編集機能があるページ：各ページフッタ上」
- **複数のページに出る設定には「サイトでの表示場所」のスライドを足す**
  - 公開側の画面を撮り、「表示されるページ」「表示される位置」「URL」を並べる。
  - 採用サイト設定・共通ブロック・フッターなど、1か所で直すと複数ページが変わるものが対象。
- **手順の説明に、表示される場所を書く**
  - ×「案内文」→ ○「画像の横に表示される文章」
  - ×「開催状況：「受付中」のときだけ日程の表を表示」→ ○「…表示します。次ページで入力した開催日程タブの内容が表示されます」

## 2. 文の終わり方

- **説明は言い切る**。「〜されます」「〜します」「〜できます」で終える。名詞で止めない。
  - ×「空欄なら要約なし」→ ○「空欄の場合、表示されません」
  - ×「公開日やカテゴリーなどの設定」→ ○「公開日やカテゴリーなどを設定します」
  - ×「一覧とトップページのNews欄に表示」→ ○「一覧とトップページのNews欄に表示されます」
- **「〜に」で途切れさせない**。言い切るか、「」で止める。
  - ×「開催しない年は「表示しない」に」→ ○「開催しない年は「表示しない」」または「開催しない年は「表示しない」にします」
- `steps` の見出し（太字の1行目）だけは短い操作名でよい。「「更新」をクリック」「「終了」に切り替え」のように、操作で終える。
- 人間らしく見せるための体言止め・倒置・問いかけを足さない。

## 3. 操作の言葉をそろえる

| 使わない | 使う |
|---|---|
| 押す・押して | クリック・クリックして |
| 〜にする（設定の値を変えるとき） | 〜に切り替え・〜に切り替えます |
| 選ぶ | 選択・選択します |
| マウスを乗せ | カーソルをあわせて |
| ふだん | 通常時 |
| いま・今の | 現在の |
| 〜のとき（条件） | 〜の場合 |
| 出る（表示の意味） | 表示される |

- スマートフォンの操作は「タップ」。電話番号のリンクなどは「スマホでタップすると…」と、どの機器の話かを書く。
- ボタン名・タブ名・欄の名前は、**画面に出ている文字どおりに「」で書く**。スキルが勝手に名前を付けない。
  - ×「「募集要項の表」タブ」（画面は「募集要項」）→ ○「「募集要項」タブ」
- 「表の左側」「右側」のように、画面と合わない位置で説明しない。欄の名前で言う。

## 4. 主語と対象をはっきりさせる

- 何を操作するのかを省かない。
  - ×「並べ替え」→ ○「行の並べ替え」
  - ×「カードを隠すときは…」→ ○「中途採用カードを隠すときは…」
- 1文に「何を」「どうすると」「どうなる」を入れる。主語と述語、修飾の掛かり先を読み直す。
- 「制作会社」のようなぼかした言い方はしない。連絡先の会社名がわかっていれば書く（site.json の `contact`）。わからなければユーザーに聞く。

## 5. 書いてはいけないこと

- **画面で確かめていない動作を書かない**。「自動で終了になる」「トップにも表示される」などは、撮影時に公開側で確かめたことだけを書く。確かめられなかったら、ユーザーへの報告に「未確認」として残す。
- **撮影した日のサイトの状態に頼った注意書きを書かない**。
  - ×「現在の対象年度は「2020年3月卒業予定者向け」のままです」（直した時点で古くなる）
  - サイトの直し忘れに気づいたら、マニュアルではなくユーザーへの報告に書く。
- 根拠のない補足、「〜してみましょう」のような呼びかけ、「便利です」のような感想を書かない。
- 抽象語（有効・最適・効率化・可視化など）を使わず、具体的な操作と結果を書く。

## 6. 表記

- 補助動詞はひらがな：「してください」「していただく」。形式名詞もひらがな：「すること」「ときは」。
- 数字は半角。ボタン名・URL・コードは画面のとおりに書き、言い換えない。
- 句読点は読み手が迷う所に打つ。行頭に「。」「、」だけが残る折り返しは語順を変えて直す。

## 7. 構成

- 目次（flow）・章の扉（section）・各スライドの対応を最後に照らし合わせる。
  - 章の扉の説明に書いたページが、その章に全部あること。
  - その章のスライドが、扉の説明に全部含まれていること（「勤務地」が扉に無い、などを防ぐ）。
  - 章の扉の `sub` には、その章で扱う設定を括弧で並べてよい（例：「採用サイト設定（採用の問い合わせ先情報、エントリーボタン、リクルートブロック募集項目の表示・非表示等）」）。
- 固定ページ・カスタム投稿のタブは撮影前に一覧にし、撮っていないタブが無いか確かめる（会長メッセージや「基本」タブの抜けを防ぐ）。

## 8. 書いたあとの確認（1回にまとめる）

1. `python3 -I $SKILL/scripts/check_text.py deck.json` を実行し、出た候補を1つずつ見る。スクリプトは言葉の候補を出すだけで、文の意味は判断しない。
2. 撮影した画面と並べて、欄の名前・ボタン名が画面の文字と同じか確かめる。
3. 7 の構成の照らし合わせをする。
4. 直した文が元の手順の意味（条件・否定・できる/できない・数値）から変わっていないか読み直す。

推敲は何度も全面的に書き直さず、この確認で1回にまとめる。

## 手直しの実例（人が直したもの）
