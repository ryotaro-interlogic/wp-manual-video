# マニュアルの文章の書き方

deck.json の `title` `steps` `note` `extra` `cards` `rows` と、動画の `say` を書くときに読む。
読み手は「この管理画面を初めて触る、クライアントの担当者」。WordPress の用語は知らない前提で書く。

この決まりは、スキルが出した文章を人が手直しした実例（下の「手直しの実例」）と、日本語推敲スキル japanese-writing-unified（natural-japanese-structure を含む）のうち、マニュアルに当てはまる部分をまとめたもの。

## 1. いちばん大事なこと：入力した内容が「サイトのどこに出るか」を書く

管理画面の欄の名前だけを説明しても、読み手は何が変わるのかわからない。次の3つを必ず入れる。

- **タイトルの下に、その画面で編集できるページを書く**（`where`）
  - 例：「この編集機能があるページ：「新卒採用」「中途採用」」
  - 例：「この編集機能があるページ：各ページフッタ上」
- **複数のページに出る設定には「サイトでの表示場所」のスライドを足す**
  - 公開側の画面を撮り、「表示されるページ」「表示される位置」「URL」を並べる。
  - 採用サイト設定・共通ブロック・フッターなど、1か所で直すと複数ページが変わるものが対象。
- **手順の説明に、表示される場所を書く**
  - ×「案内文」→ ○「画像の横に表示される文章」
  - ×「開催状況：「受付中」のときだけ日程の表を表示」→ ○「…表示します。次ページで入力した開催日程タブの内容が表示されます」

## 2. 文の終わり方

- **説明は言い切る**。「〜されます」「〜します」「〜できます」で終える。名詞で止めない。
  - ×「空欄なら要約なし」→ ○「空欄の場合、表示されません」
  - ×「公開日やカテゴリーなどの設定」→ ○「公開日やカテゴリーなどを設定します」
  - ×「一覧とトップページのNews欄に表示」→ ○「一覧とトップページのNews欄に表示されます」
- **「〜に」で途切れさせない**。言い切るか、「」で止める。
  - ×「開催しない年は「表示しない」に」→ ○「開催しない年は「表示しない」」または「開催しない年は「表示しない」にします」
- `steps` の見出し（太字の1行目）だけは短い操作名でよい。「「更新」をクリック」「「終了」に切り替え」のように、操作で終える。
- 人間らしく見せるための体言止め・倒置・問いかけを足さない。

## 3. 操作の言葉をそろえる

| 使わない | 使う |
|---|---|
| 押す・押して | クリック・クリックして |
| 〜にする（設定の値を変えるとき） | 〜に切り替え・〜に切り替えます |
| 選ぶ | 選択・選択します |
| マウスを乗せ | カーソルをあわせて |
| ふだん | 通常時 |
| いま・今の | 現在の |
| 〜のとき（条件） | 〜の場合 |
| 出る（表示の意味） | 表示される |

- スマートフォンの操作は「タップ」。電話番号のリンクなどは「スマホでタップすると…」と、どの機器の話かを書く。
- ボタン名・タブ名・欄の名前は、**画面に出ている文字どおりに「」で書く**。スキルが勝手に名前を付けない。
  - ×「「募集要項の表」タブ」（画面は「募集要項」）→ ○「「募集要項」タブ」
- 「表の左側」「右側」のように、画面と合わない位置で説明しない。欄の名前で言う。

## 4. 主語と対象をはっきりさせる

- 何を操作するのかを省かない。
  - ×「並べ替え」→ ○「行の並べ替え」
  - ×「カードを隠すときは…」→ ○「中途採用カードを隠すときは…」
- 1文に「何を」「どうすると」「どうなる」を入れる。主語と述語、修飾の掛かり先を読み直す。
- 「制作会社」のようなぼかした言い方はしない。連絡先の会社名がわかっていれば書く（site.json の `contact`）。わからなければユーザーに聞く。

## 5. 手順を絞る

画面にある欄を上から全部並べると、どれが大事なのかわからなくなり、機械が書いた資料に見える。読み手が実際に操作するものだけを手順にする。

- **番号を付けるのは、必ず入力する欄とクリックするボタンだけ**。（任意）の欄や通常は触らない欄は、番号を付けずに、関係する手順の説明に1文でまとめる。
  - ×「3 メールアドレス（任意）」「4 受講する講座（任意）」「5 新しいパスワード（任意）」を別々の番号にする
  - ○ 必須の欄と「登録する」に番号を付け、「メールアドレス・受講する講座・パスワードは、必要な場合だけ入力します」と書く
- **説明は、見出しだけではわからないことがあるときだけ書く**。見出しを言い換えただけの説明は書かず、空文字にする。
  - ×「パスワードを入力」／「管理者のパスワードを入力します」→ ○ 説明は空文字
  - ×「「保存する」をクリック」／「変更内容が保存されます」→ ○ 空文字か、「受講者の画面にすぐ反映されます」のように読み手が知りたい結果
- 説明に書くもの：入力した内容がサイトのどこに表示されるか、入力の決まり（半角英数字など）、クリックした後に何が表示されるか（次の画面が見てわかるなら書かない）、取り消せないこと。
- 手順の数や説明の長さをそろえない。手順が1つなら1つ、説明が要らない手順は空のままでよい。
- 1枚の手順は5つまでを目安にする。超えるときは画面を分けるか、任意の欄をまとめる。

## 6. 「ポイント」と「注意」の使い分け（note）

note は、本当に必要なスライドにだけ付ける。全部のスライドに付けると、どれも目に入らなくなる（目安は全体の3分の1以下、1枚に1つ）。

| 種類 | 書くこと | 例 |
|---|---|---|
| 注意（`"kind": "warn"`） | やると取り消せないこと、サイトやメールに影響が出ること、やってはいけないこと | 「デフォルト通知」の宛先を変えると、お問い合わせが届かなくなります |
| ポイント（`kind` なし） | 知らないと迷うこと、つまずきやすいこと、その場合の確認先 | 作ったフォームが一覧に表示されないときは、フォームを保存したか確かめてください |

どちらにも当てはまらないものは note にしない。

- 操作の手順（「〜をクリックします」）は `steps` に書く。
  - ×注意「入力後、ページ最下部の「変更を保存する」をクリックします」→ ○ 手順の最後に「「変更を保存する」をクリック」を足す
- URL などの情報は `extra` に書く。
  - ×ポイント「URL：https://〇〇.jp/ 受講者と同じログイン画面です」→ ○ extra の「ログイン画面のURL」
- 手順の補足は、その手順の説明に書く。

## 7. タイトルと「この編集機能があるページ」（where）

- **タイトルは、そのスライドでやることを短く書く**。ボタン名から始めるより、やることから始めるほうが目次として読みやすい。
  - ×「「招待URLを発行」で登録用URLを作る」→ ○「受講者に送る登録用URLを作る」
- 「「〇〇」で〜する」「「〇〇」をクリックして〜する」のように、同じ形のタイトルを続けない（3枚続いたら変える）。
- タイトルに句点「。」を付けない。
- **`where` は、その画面で入力した内容がサイトに表示されるスライドにだけ付ける**。ログイン、メニューの説明、ダッシュボード、一覧の確認など、表示に関係しない画面は `"noWhere": true` にする。
- `where` には、サイトのページ名（「新卒採用」「各ページのフッター上」など）を書く。管理画面の場所（「メニュー「講座管理」の右上」など）は書かない。管理画面の場所は、タイトルか手順で示す。

### 管理画面とサイトを並べる（compare）

- ACF のタブ・入力欄を説明するときは、管理画面だけのスライドより `compare` を先に考える。左の欄と右の表示が同じ番号になるようにする。
- 手順の見出しは欄の名前（画面のとおり）、説明はサイトでの出方（「1行ずつ別々の欄に」「空欄なら非表示」）。
- サイトに出ない欄は、説明に「現在は表示なし」と書く。

### ログインのスライド

- `extra` の見出しは「ログイン情報」。URL・ユーザー名・パスワードを1行ずつ書く（`{{editor.user}}` `{{editor.pass}}`）。
- 手順の説明は「下の「ログイン情報」のユーザー名」のように extra を指す。

## 8. 書いてはいけないこと

- **画面で確かめていない動作を書かない**。「自動で終了になる」「トップにも表示される」などは、撮影時に公開側で確かめたことだけを書く。確かめられなかったら、ユーザーへの報告に「未確認」として残す。
- **撮影した日のサイトの状態に頼った注意書きを書かない**。
  - ×「現在の対象年度は「2020年3月卒業予定者向け」のままです」（直した時点で古くなる）
  - サイトの直し忘れに気づいたら、マニュアルではなくユーザーへの報告に書く。
- 根拠のない補足、「〜してみましょう」のような呼びかけ、「便利です」のような感想を書かない。
- 抽象語（有効・最適・効率化・可視化など）を使わず、具体的な操作と結果を書く。

## 9. 表記

- 補助動詞はひらがな：「してください」「していただく」。形式名詞もひらがな：「すること」「ときは」。
- 数字は半角。ボタン名・URL・コードは画面のとおりに書き、言い換えない。
- 句読点は読み手が迷う所に打つ。改行の位置はスライドを作るときに自動で決まる（文節の切れ目・禁則）。1行に1〜2文字だけ残る折り返しが出たら、語順を変えて直す。

## 10. 構成

- 表紙の次は目次（`toc`）。「このマニュアルで説明すること」のようなページは作らない。
- 目次（toc）・章の扉（section）・各スライドの対応を最後に照らし合わせる。
  - 章の扉の説明に書いたページが、その章に全部あること。
  - その章のスライドが、扉の説明に全部含まれていること（「勤務地」が扉に無い、などを防ぐ）。
  - 章の扉の `sub` には、その章で扱う設定を括弧で並べてよい（例：「採用サイト設定（採用の問い合わせ先情報、エントリーボタン、リクルートブロック募集項目の表示・非表示等）」）。
- 固定ページ・カスタム投稿のタブは撮影前に一覧にし、撮っていないタブが無いか確かめる（会長メッセージや「基本」タブの抜けを防ぐ）。

## 11. 書いたあとの確認（1回にまとめる）

1. `python3 -I $SKILL/scripts/check_text.py deck.json` を実行し、出た候補を1つずつ見る。スクリプトは言葉の候補を出すだけで、文の意味は判断しない。
2. 撮影した画面と並べて、欄の名前・ボタン名が画面の文字と同じか確かめる。
3. 10 の構成の照らし合わせをする。
4. 直した文が元の手順の意味（条件・否定・できる/できない・数値）から変わっていないか読み直す。

推敲は何度も全面的に書き直さず、この確認で1回にまとめる。
